# 4. 안드로이드 폰 세팅 (문자·카톡·통화·음성메모 → 서버)

원장 폰에 오는 **문자·카톡 알림·통화 녹음·음성메모**를 서버 수신함으로 자동 전송합니다.
앱은 **MacroDroid**(Play 스토어, 무료 버전으로 충분) 하나만 씁니다. 원리는 전부 같습니다:

> "폰에서 무슨 일이 생기면(트리거) → 서버 주소로 HTTP POST 한 번(액션)"

3단계에서 비서가 알려준 두 값이 필요합니다: **터널 주소**(`https://xxxx.trycloudflare.com`)와 **INBOX_TOKEN**.

이 문서는 실제로 두 달 넘게 운영하면서 넘어진 자리를 전부 적었습니다(4-6절).
**표 대로 만들고, 4-6절을 한 번 훑어보세요.** 열에 아홉은 거기 있는 문제입니다.

---

## 4-0. 먼저: 폰 권한·설정 (이거 안 하면 며칠 뒤 조용히 멈춥니다)

| 어디서 | 무엇을 | 왜 |
|---|---|---|
| 설정 → 앱 → MacroDroid → **배터리** | **제한 없음(최적화 안 함)** | 절전에 들어가면 백그라운드 HTTP 가 안 나갑니다. 낮에 되다가 밤에 멈추는 전형적 원인 |
| 설정 → 알림 → 고급 → **기기 및 앱 알림 접근(알림 접근 권한)** | MacroDroid **허용** | 카톡은 "알림"을 읽어서 가져오므로 이게 없으면 카톡 매크로가 아예 안 뜹니다 |
| MacroDroid 첫 실행 | **SMS 읽기 / 전화 / 저장공간(모든 파일 접근)** 권한 허용 | 문자 매크로·통화 매크로·파일 업로드 각각에 필요 |
| 설정 → 잠금화면 → 알림 | **내용 표시(숨기지 않음)** | "내용 숨김"이면 알림 본문이 비어서 카톡 본문이 빈 채로 옵니다 |
| MacroDroid 설정 | **"기기 부팅 시 자동 시작"** 켜기 | 재부팅 후 매크로가 안 살아나는 걸 막습니다 |
| 카카오톡 → 채팅방 → 알림 | 가져오고 싶은 방은 **알림 켜짐** | 방 알림을 끄면 안드로이드 알림 자체가 안 생기므로 매크로가 발동할 수가 없습니다 |

## 4-1. 문자 전달 매크로

MacroDroid → **매크로 추가** → 이름 `문자전달`:

| 항목 | 설정 |
|---|---|
| **트리거** | **SMS 수신** → 발신자: 아무나(모든 번호) |
| **액션** | **HTTP 요청(HTTP Request)** |
| · 방법 | POST |
| · URL | `https://<터널주소>/sms` |
| · 헤더 파라미터 | `X-Internal-Token` = `<INBOX_TOKEN>` |
| · 본문(Body) 내용 | **파라미터(Form / x-www-form-urlencoded)** |
| · 파라미터 | `from` = `{sms_number}` / `text` = `{sms_message}` / `ts` = `{hour}:{minute}` |
| · 문자 인코딩 | UTF-8 (기본값 그대로) |

변수는 `{ }` 로 직접 타이핑해도 되고, 입력칸 옆 `...` 버튼에서 "SMS 번호 / SMS 메시지"를 고르면 들어갑니다.

저장하고 **다른 폰에서 원장 폰으로 문자를 하나 보내보세요.**
서버에서 `python3 scripts/inbox-ack.py --status` 를 치면 미처리 1건이 보이고, 1분 안에 비서가 텔레그램으로 그 문자를 정리해 보고합니다.

광고·스팸도 그대로 보냅니다. 폰에서 거르지 마세요. 거르는 건 비서가 합니다(4-6절 "폰에서 거르지 마라").

## 4-2. 카톡 알림 전달 매크로

카톡은 API 가 없어서 **알림에 뜨는 텍스트**를 읽습니다. 알림에 뜨는 만큼만 옵니다.

| 항목 | 설정 |
|---|---|
| **트리거** | **알림 수신(Notification Received)** → 앱 선택: **카카오톡** 만 체크 |
| · 트리거 옵션 | "알림 텍스트에 포함된 단어" **비워두기(조건 없음)** ← 중요, 4-6절 ① |
| · | "같은 알림 무시(Ignore ongoing)" 켜기, "그룹 요약 알림 무시" 켜기 |
| **액션** | HTTP 요청 POST `https://<터널주소>/sms` , 헤더 `X-Internal-Token` 동일 |
| · 파라미터 | `app` = `{not_app_name}` / `from` = `{not_title}` / `text` = `{notification}` / `ts` = `{hour}:{minute}` |

- `app` 에 "카카오톡"이 들어오면 서버가 문자와 구분해 `kakao` 로 기록합니다. 이 값이 빠지면 문자로 분류됩니다.
- `{not_title}` 에는 **보낸 사람 이름**이 들어옵니다(1:1 이든 단톡방이든). **방 이름은 안 들어옵니다** — 4-6절 ①.
- 사진·이모티콘은 "사진을 보냈습니다"로만 옵니다. 그건 원장이 카톡을 직접 보는 수밖에 없습니다.

**방 단위로 거르려고 하지 마세요.** 카톡 전체를 다 받고, 업무인지 잡담인지는 비서가 내용을 보고 판단합니다. 이 결론에 도달하기까지 8일을 잃었습니다(4-6절 ①).

## 4-3. 통화 녹음 전달 (선택 — STT 키 필요)

통화 내용까지 비서가 요약하게 하려면 `.env` 에 `SONIOX_API_KEY` 를 넣고(soniox.com, 종량제) 매크로를 **두 개** 만듭니다.
하나로 만들면 부재중 전화 때 **직전 통화 녹음이 다시 올라가는** 사고가 납니다(4-6절 ④). 두 개인 이유가 그것입니다.

전제: 폰의 **통화 자동 녹음**이 켜져 있어야 합니다. 갤럭시는 전화 앱 → 설정 → 통화 녹음 → 자동 녹음. 녹음 파일은 보통 `내장저장공간/Recordings/Call/` 에 생깁니다(기종마다 다르니 파일 앱에서 통화 한 번 해보고 어디 생기는지 확인).
아이폰·일부 통신사 폰은 통화 녹음이 아예 안 됩니다. 그럼 이 절은 건너뛰고 문자·카톡만으로 시작해도 충분히 쓸모 있습니다.

### 매크로 A — `통화녹음감지` (파일이 생기면 이름만 기억)

| 항목 | 설정 |
|---|---|
| **트리거** | **변경된 파일(File Changed)** → 폴더: 통화 녹음 폴더 / 파일 이름 필터 `*` / 이벤트: **생성됨만 체크**(삭제·수정은 해제) |
| **액션** | **변수 설정** → 전역 변수 `callfile`(문자열, 없으면 새로 만들기) = `{file_name}` |

### 매크로 B — `통화전송` (전화가 끊기면 그 파일을 올림)

| 순서 | 액션 |
|---|---|
| **트리거** | **통화 종료(Call Ended)** → 아무 번호나 |
| 1 | **대기(Wait before next action)** 5초 ← 녹음 파일이 다 저장될 시간 |
| 2 | **if (조건)** → 조건: MacroDroid 변수 `callfile` **!=** (값 비워둠 = 빈 문자열) |
| 3 | ㄴ **HTTP 요청** POST `https://<터널주소>/call?number={call_number}&name={call_name}` , 헤더 `X-Internal-Token` |
| | ㄴ 본문 내용 = **파일 업로드** → 파일 선택 방식: **동적 파일 이름(스토리지 액세스 프레임워크)** → 폴더 = 통화 녹음 폴더, 파일 이름 = `{callfile}` , 파라미터 이름 `file` |
| 4 | **End if** |
| 5 | **변수 설정** `callfile` = (빈 값) ← if 밖에 둡니다. 매 통화마다 무조건 비워서 오래된 파일명이 남지 않게 |

동작 원리: A 는 **진짜 녹음이 생겼을 때만** 파일명을 채웁니다. 부재중 전화는 녹음이 없으니 A 가 안 뜨고, B 의 if 가 빈 값이라 전송을 건너뜁니다. 전송 뒤엔 비워서 다음 부재중도 건너뜁니다.

MacroDroid 메뉴에서 실제로 누르는 순서(헤맨 자리):
1. 매크로 B 액션 **+** → 검색 "조건" → **"if (조건) … 동작"** 추가
2. 조건 추가 → 목록 맨 아래 **"MacroDroid 관련" → "MacroDroid 변수"** → `callfile` 선택 → 비교 **!=** → 값 칸 **빈 채로** 확인(빈 값 비교가 됩니다)
3. 액션 목록 오른쪽 **↕** 로 "if" 줄을 HTTP 요청 **위로** 드래그해서 HTTP 가 if 안쪽(들여쓰기)에 들어가게
4. 저장 ✓

## 4-4. 음성메모 전달 (선택 — STT 키 필요)

걸어가면서 "내일 3시 김OO 어머님 상담" 같은 걸 흘려 말하면 비서가 받아 적는 기능입니다.

녹음은 **폰 기본 녹음기 앱**으로 하고(잠금화면에서 녹음기 열어 녹음 → 정지 → 저장), 파일이 생기면 매크로가 올립니다.
MacroDroid 안에서 직접 녹음하는 방식은 버렸습니다(4-6절 ⑥).

| 항목 | 설정 |
|---|---|
| **트리거** | **변경된 파일** → 폴더: 녹음기 저장 폴더(갤럭시 = `Recordings/Voice Recorder`) / 파일 필터 `*.m4a` / **생성됨만 체크** |
| 액션 1 | 대기 3초 |
| 액션 2 | HTTP 요청 POST `https://<터널주소>/voice` , 헤더 `X-Internal-Token` , 본문 = 파일 업로드(동적 파일 이름, 폴더 = 그 폴더, 파일 이름 = `{file_name}` , 파라미터 이름 `file`) |

블루투스 이어폰 마이크로 녹음하고 싶으면 **삼성 녹음기 → 설정 → "사용 가능할 때 블루투스 마이크 사용"** 을 켭니다. 이 토글 하나가 답이고, 다른 녹음 앱·라우팅 앱은 전부 실패했습니다(4-6절 ⑦).

## 4-5. 서버에서 확인하는 법

```bash
journalctl -u inbox-server -n 50 --no-pager      # 도착했나, 401(토큰) 인가, 빈 본문인가
python3 scripts/inbox-ack.py --status            # 수신함 몇 건, 미처리 몇 건
tail -3 data/inbox.jsonl                         # 실제로 뭐가 들어왔나 (from / text / app)
```

MacroDroid 쪽은 매크로 화면 → **시스템 로그**(왼쪽 메뉴)에서 "발동했는지 / HTTP 응답 코드가 뭔지"를 봅니다.
**폰 로그의 발동 시각과 서버 journal 의 도착 시각이 초 단위로 맞으면 전송은 정상**이고, 문제는 내용(변수)입니다.

## 4-6. 시행착오 전부 (증상 → 원인 → 해결)

두 달 운영하며 실제로 겪은 것만 적었습니다. 위에서부터 자주 걸리는 순서입니다.

### ① 카톡이 어느 날부터 조용히 0건 (8일간 모르고 지나감)
- **증상**: 문자·통화는 잘 오는데 카톡만 어느 날 이후 한 건도 안 옴. 에러도 없음.
- **헛다리 1**: "알림 접근 권한이 풀렸나 / 배터리 최적화에 걸렸나" → 같은 MacroDroid 가 문자·통화는 그날도 보내고 있었으니 **처음부터 아닌 걸 알 수 있었던 가설**. 절전 화면의 큰 숫자에 꽂혀 두 시간 낭비.
- **헛다리 2**: "그 채팅방 알림을 꺼뒀나" → 켜 있었음.
- **진짜 원인**: 카톡 앱 업데이트로 알림이 **대화형(MessagingStyle) 형식**으로 바뀌면서, 방 이름이 매크로가 읽는 **제목 칸에서 다른 칸으로 옮겨갔습니다.** 트리거에 걸어둔 조건 "알림 텍스트에 `선생님방` 포함"이 더는 어디에도 안 맞아서 발동을 안 한 것. 화면엔 방 이름이 멀쩡히 보이니 사람 눈엔 아무것도 안 바뀐 것처럼 보였습니다.
- **해결**: 트리거의 **포함 단어 조건을 지움** → 그 즉시 유입 재개. 방 이름이 담기는 변수를 찾으려고 `{not_title}` `{not_text_lines}` `{not_ticker}` 등 후보를 전부 실어 보내 서버 로그로 봤는데, **방 이름은 어느 변수에도 없었습니다**(티커는 "보낸사람 : 내용"). 그래서 방 단위 필터는 포기하고 **카톡 전체를 다 받고 비서가 내용으로 업무/잡담을 가르는** 구조로 확정.
- **교훈**: 필터가 갑자기 안 걸리면 "값이 바뀌었나"보다 **"값이 다른 자리로 갔나"**를 먼저 의심. 그리고 소스별로 "48시간 0건이면 알려줘" 같은 침묵 감시를 서버에 두세요(이번 레포의 비서는 CLAUDE.md 규칙으로 0건 보고를 하게 돼 있습니다).
- **잃은 것**: 그 8일치 단톡방 공지는 서버에 도착한 적이 없어서 복구 불가. 원장이 폰으로 스크롤해 봐야 했습니다.

### ② 매크로 "테스트 실행" 버튼을 누르면 `{notification}` 이 글자 그대로 옴
- **증상**: 서버에 `text={notification}`, `from={not_title}` 처럼 **중괄호 변수명이 치환 안 된 채** 도착.
- **원인**: 매크로 화면의 ▶ 테스트 실행은 **트리거를 건너뛰므로** 트리거가 채우는 변수가 전부 빈 값입니다. 고장이 아닙니다.
- **해결**: 카톡 매크로 테스트는 **가족·지인에게 실제 카톡 한 통 보내달라고** 해서 합니다. 문자 매크로는 다른 폰에서 문자 한 통.

### ③ 같은 카톡이 2~3번 연속 옴 (밀리초 간격)
- **증상**: "아멘 감사합니다" 같은 짧은 메시지 하나가 서버에 3건 연속 도착.
- **원인**: 카톡이 알림을 **갱신**(그룹 요약·읽음 상태 변화)할 때마다 안드로이드는 새 알림 이벤트를 쏘고, MacroDroid 가 그때마다 발동합니다. 큰 텍스트 칸엔 최근 메시지 여러 줄이 누적돼 있기도 합니다.
- **해결**: 폰에서는 트리거 옵션 "그룹 요약 알림 무시"를 켜고, **서버가 60초 안 같은 발신자·같은 본문은 버립니다**(이 레포 `inbox_server.py` 의 `_is_dup`). 폰 설정만으로는 완전히 못 막아서 서버 쪽 방어가 정답이었습니다.

### ④ 부재중 전화인데 "직전 통화" 내용이 또 요약돼 옴
- **증상**: 18:34 정상 통화 요약 → 19:04 부재중 전화 뒤 **똑같은 요약이 다른 번호 이름으로** 한 번 더 옴. 가끔은 5KB 짜리 깨진 조각이 올라와 전사 실패.
- **원인**: "통화 종료" 트리거 하나에 "통화 녹음 폴더의 **최신 파일** 업로드"를 걸어두면, 부재중(녹음 없음)에도 트리거는 발동하고 최신 파일 = **지난 통화 녹음**이 다시 올라갑니다.
- **해결**: 4-3절의 **A/B 두 매크로 + 전역 변수 `callfile` + if 가드** 구조. 녹음 파일이 실제로 생겼을 때만 파일명이 채워지고, 전송 후 비웁니다. 서버도 이중으로 **같은 오디오(sha256)가 6시간 안에 또 오면 버립니다**(`/call`).
- **부수 확인**: 정상 통화가 이 가드에 걸려 안 올라가면 대기 시간을 5초 → 8~10초로 늘리세요(녹음 파일 저장이 통화 종료보다 늦게 끝나는 기종).

### ⑤ 통화 요약은 오는데 "누구랑" 통화했는지 없음
- **증상**: 전사 텍스트만 오고 상대 번호·이름이 없어서 비서가 학부모를 못 찾음.
- **원인**: 녹음 파일엔 번호가 없습니다. 파일 이름에 번호가 들어가긴 하지만 기종·앱마다 형식이 달라 파싱이 깨집니다.
- **해결**: HTTP 요청 URL 에 **쿼리로** 붙입니다: `/call?number={call_number}&name={call_name}`. 발신/수신 구분이 필요하면 `&dir=out` 을 발신용 매크로에만 붙이면 됩니다. 본문은 파일이라 다른 값을 실을 자리가 쿼리·헤더뿐입니다.

### ⑥ MacroDroid 안에서 직접 녹음하면 반쪽만 올라옴
- **증상**: 긴 음성메모가 앞부분만 전사됨, 또는 0바이트로 도착("녹음이 비어서 도착").
- **원인**: 녹음 액션 뒤 바로 업로드하면 파일이 아직 다 안 써진 상태. 대기를 늘려도 녹음 길이에 따라 어긋남. 파일 업로드 본문 설정을 "텍스트"로 두면 내용 없이 파일명만 갑니다.
- **해결**: 녹음은 **기본 녹음기 앱**에 맡기고, 매크로는 **"변경된 파일 → 생성됨만"** 트리거로 완성된 파일만 잡습니다. 삼성 녹음기는 정지 후 저장(확인) 시점에 파일을 만들기 때문에 길이와 무관하게 항상 완성본입니다. 본문은 반드시 **파일 업로드 / 동적 파일 이름 / 파라미터명 `file`**. "삭제됨·수정됨"까지 체크하면 저장 중 여러 번 발동해 반쪽이 여러 번 갑니다.

### ⑦ 블루투스 이어폰 마이크로 녹음이 안 됨
- **증상**: 이어폰을 껴도 폰 마이크로만 녹음됨.
- **헛다리**: 서드파티 녹음기(Hi-Q 등), 마이크 라우팅 앱, MacroDroid "연결 도우미"(이건 출력 A2DP 만 제어하고 입력은 못 바꿈) 전부 실패. USB-C 무선마이크 리시버는 되지만 "꽂았다 뺐다" 가 번거로워 기각.
- **해결**: **삼성 기본 녹음기 → 설정 → "사용 가능할 때 블루투스 마이크 사용" ON.** 이게 진짜 스위치입니다. 음질은 전화 음질(8kHz)이지만 STT 에는 충분(4.3MB → 889자 온전 전사 확인).

### ⑧ 서버 응답 401
- **원인**: 헤더 이름 오타(`X-Internal-Token`), 토큰 앞뒤 공백, 토큰 회전 후 폰 미갱신.
- **해결**: 서버 `.env` 의 값과 매크로 헤더 값을 글자 단위로 대조. **토큰을 바꿨으면 매크로 4개 전부** 바꿔야 합니다(하나만 바꾸고 나머지가 조용히 401 나는 일이 실제로 있었습니다).

### ⑨ 터널 주소가 바뀜 (quick tunnel 재시작)
- **증상**: 어느 날부터 전부 안 옴, MacroDroid 로그엔 연결 실패.
- **원인**: 무료 quick tunnel 은 재시작마다 주소가 바뀝니다.
- **해결**: 매크로 4개의 URL 호스트를 바꿉니다. 매번 귀찮으면 Cloudflare 에 도메인을 하나 붙여 **고정 주소 터널**(3단계 문서 참고)로 바꾸는 게 근본 해결입니다. 서버 쪽 경로 이름(`/sms` `/call` `/voice`)은 **절대 바꾸지 마세요** — 바꾸면 폰 매크로를 전부 다시 만져야 합니다.

### ⑩ 한글이 `??` 나 깨진 글자로 옴
- **원인**: HTTP 요청 본문 인코딩이 UTF-8 이 아니거나, 서버가 본문을 latin-1 로 읽음.
- **해결**: 매크로 본문 인코딩 UTF-8(기본값). 이 레포 서버는 본문을 UTF-8 로 강제 디코드합니다. JSON 대신 Form 파라미터를 권하는 이유도 MacroDroid 에서 JSON 을 손으로 쓰면 따옴표·줄바꿈 이스케이프에서 자주 깨지기 때문입니다.

### ⑪ 폰에서 거르지 마라
- 처음엔 광고 문자·잡담 카톡을 폰 매크로 조건으로 걸러 보려 했습니다. 결과는 ①번 사고와 "새로 온 선생님 카톡을 명단에 없다고 조용히 버림"이었습니다.
- **원칙**: 폰은 **다 보내고**, 거르는 건 서버·비서가 합니다. 폰 쪽 필터는 고장 나도 아무도 모릅니다(조용히 0건). 서버 쪽 필터는 로그가 남습니다.

### ⑫ 재부팅·업데이트 뒤 매크로가 꺼져 있음
- **원인**: MacroDroid 자동 시작 꺼짐, 또는 안드로이드 대규모 업데이트 뒤 알림 접근 권한이 초기화됨.
- **해결**: 4-0 절 표를 다시 한 번. 그리고 서버 쪽 "48시간 침묵 감시"가 있으면 이걸 이틀 안에 잡습니다. 없으면 8일 갑니다(①).
