# 4. 안드로이드 폰 세팅 (문자·카톡·통화·음성메모 → 서버)

원장 폰에 오는 **문자·카톡 알림·통화 녹음·음성메모**를 서버 수신함으로 자동 전송합니다.
앱은 **MacroDroid**(Play 스토어, 무료 버전으로 충분) 하나만 씁니다. 원리는 전부 같습니다:

> "폰에서 무슨 일이 생기면(트리거) → 서버 주소로 HTTP POST 한 번(액션)"

3단계에서 비서가 알려준 두 값이 필요합니다: **터널 주소**(`https://xxxx.trycloudflare.com`)와 **INBOX_TOKEN**.
토큰은 **폰에 직접 타이핑**하세요. 카톡·텔레그램 채팅으로 자기한테 보내두면 채팅 기록에 평문으로 남습니다(우리가 그렇게 했다가 토큰을 바꿔야 했습니다).

이 문서는 실제 두 달 넘게 운영하면서 넘어진 자리를 전부 적었습니다(4-6절, 17건).
**표대로 만들고, 4-6절을 한 번 훑어보세요.** 열에 아홉은 거기 있는 문제입니다.

---

## 4-0. 먼저: 폰 권한·설정 (이거 안 하면 며칠 뒤 조용히 멈춥니다)

| 어디서 | 무엇을 | 왜 |
|---|---|---|
| 설정 → 앱 → MacroDroid → **배터리** | **제한 없음(최적화 안 함)** | 절전에 들어가면 백그라운드 HTTP 가 안 나갑니다. 낮에 되다가 밤에 멈추는 전형적 원인 |
| 설정 → 알림 → 고급 → **기기 및 앱 알림 접근** | MacroDroid **허용** | 문자·카톡 둘 다 "알림"을 읽어서 가져옵니다. 이게 없으면 매크로가 아예 안 뜹니다 |
| 설정 → 접근성 → 설치된 앱 | **MacroDroid(UI 자동조작) 허용** | 알림 버튼·위젯 트리거가 이 권한을 요구합니다. 안 주면 권한 팝업이 무한 반복됩니다(4-6절 ①) |
| MacroDroid 첫 실행 | **전화 / 저장공간(모든 파일 접근)** 권한 허용 | 통화 매크로·파일 업로드에 필요 |
| 설정 → 잠금화면 → 알림, 그리고 카톡 → 설정 → 알림 | **내용(미리보기) 표시** | "내용 숨김"이면 알림 본문이 비어서 빈 문자가 옵니다 |
| MacroDroid 설정 | **"기기 부팅 시 자동 시작"** 켜기 | 재부팅 후 매크로가 안 살아나는 걸 막습니다 |
| 카카오톡 → 채팅방 → 알림 | 가져오고 싶은 방은 **알림 켜짐** | 방 알림을 끄면 안드로이드 알림 자체가 안 생기므로 매크로가 발동할 수가 없습니다 |

HTTP 요청 액션의 공통 설정(모든 매크로 동일): 방법 **POST**, 설정 탭에서 "리디렉션 따름"만 체크, 헤더 `X-Internal-Token` = `<INBOX_TOKEN>`(헤더 이름은 대소문자 구분 안 함), 문자 인코딩 UTF-8.
`{ }` 변수(매직 텍스트)는 **손으로 타이핑하지 말고 입력칸 옆 `...` 버튼으로 삽입**하세요(4-6절 ③).

## 4-1. 문자 전달 매크로

MacroDroid → **매크로 추가** → 이름 `문자전달`:

| 항목 | 설정 |
|---|---|
| **트리거** | **알림 수신됨(Notification Received)** → 앱 선택: 삼성 **메시지**(문자 앱) 만 체크, 텍스트 조건 없음 |
| · 트리거 옵션 | **"같은 알림 중복 무시(연속 발동 방지)" 끔** ← 같은 내용의 문자가 두 번 오면 둘째가 안 오던 원인 |
| **액션** | HTTP 요청 POST `https://<터널주소>/sms` |
| · 본문 형식 | 파라미터(Form / x-www-form-urlencoded) |
| · 파라미터 | `from` = `{not_title}` / `text` = `{notification}` / `ts` = `{hour}:{minute}` |

⚠️ 트리거를 **"SMS 수신"으로 하지 마세요.** 그 트리거는 **MMS(긴 문자·사진 문자)를 아예 못 봅니다.** 짧은 문자만 오고 긴 문자는 조용히 빠집니다(4-6절 ④). 알림 수신 방식은 문자·MMS 모두 잡히고, 대신 `from` 에 번호가 아니라 **연락처 저장 이름**이 옵니다(저장 안 된 번호는 번호 그대로). 서버는 이름 앞뒤에 붙는 보이지 않는 유니코드 기호를 벗겨서 저장합니다.

저장하고 **다른 폰에서 원장 폰으로 문자를 하나 보내보세요.** 내 폰에서 내 폰으로 보낸 문자는 알림이 안 떠서 테스트가 안 됩니다.
서버에서 `python3 scripts/inbox-ack.py --status` 를 치면 미처리 1건이 보이고, 1분 안에 비서가 텔레그램으로 그 문자를 정리해 보고합니다.

광고·스팸도 그대로 보냅니다. 폰에서 거르지 마세요. 거르는 건 비서가 합니다(4-6절 ⑤·⑮).

## 4-2. 카톡 알림 전달 매크로

문자 매크로를 **복제**해서 앱만 바꿉니다. 한 매크로에 두 앱을 넣고 조건을 걸면 문자까지 막히므로 반드시 분리합니다.

| 항목 | 설정 |
|---|---|
| **트리거** | 알림 수신됨 → 앱 선택: **카카오톡** 만 체크 |
| · 트리거 옵션 | 텍스트 조건 **비워두기(조건 없음)** ← 중요, 4-6절 ⑨ / "같은 알림 중복 무시" **끔**(단톡방 연속 메시지 누락 방지) / "그룹 요약 알림 무시" 켜기 |
| **액션** | HTTP POST `https://<터널주소>/sms` (문자와 같은 주소) |
| · 파라미터 | `app` = `카카오톡`(그냥 글자) / `from` = `{not_title}` / `text` = `{notification}` / `ts` = `{hour}:{minute}` |

- `app` 에 "카카오톡"이 있으면 서버가 문자와 구분해 `kakao` 로 기록합니다. 이 값이 빠지면 문자로 분류됩니다.
- `{not_title}` 에는 **보낸 사람 이름**이 들어옵니다(1:1 이든 단톡방이든). **방 이름은 어느 변수에도 안 들어옵니다** — 4-6절 ⑨.
- 사진·이모티콘은 "사진을 보냈습니다"로만 옵니다. 묶음 알림("메시지 N개")이면 개별 본문이 빠질 수 있습니다. 원장이 보낸 메시지·과거 메시지는 안 옵니다(새로 받은 것만).

**방 단위로 거르려고 하지 마세요.** 카톡 전체를 다 받고, 업무인지 잡담인지는 비서가 내용을 보고 판단합니다. 이 결론에 도달하기까지 8일을 잃었습니다(4-6절 ⑨).

## 4-3. 통화 녹음 전달 (선택 — STT 키 필요)

통화 내용까지 비서가 요약하게 하려면 `.env` 에 `SONIOX_API_KEY` 를 넣고(soniox.com, 종량제) 매크로를 **두 개** 만듭니다.
하나로 만들면 **통화 시작 시점의 미완성 파일**이 올라가거나(4-6절 ⑥), 부재중 전화 때 **직전 통화 녹음이 다시 올라갑니다**(4-6절 ⑧). 두 개인 이유가 그것입니다.

전제: 폰의 **통화 자동 녹음**이 켜져 있어야 합니다. 갤럭시는 전화 앱 → 설정 → 통화 녹음 → 자동 녹음. 녹음 파일은 `내장저장공간/Recordings/Call/` 에 `통화 이름_날짜.m4a` 로 생깁니다(기종마다 다르니 파일 앱에서 통화 한 번 해보고 확인).
아이폰·일부 통신사 폰은 통화 녹음이 아예 안 됩니다. 그럼 이 절은 건너뛰고 문자·카톡만으로 시작해도 충분히 쓸모 있습니다.

### 매크로 A — `통화녹음감지` (파일이 생기면 이름만 기억)

| 항목 | 설정 |
|---|---|
| **트리거** | **변경된 파일(File Changed)** → 폴더: 통화 녹음 폴더(`Recordings/Call`) / 파일 이름 필터 `*` / 이벤트: **생성됨만 체크** |
| **액션** | **변수 설정** → 전역 변수 `callfile`(문자열, 없으면 새로 만들기) = 매직 텍스트 **"파일 이름"** (`{file_name}`) — **경로가 아니라 이름만**(4-6절 ⑦) |

### 매크로 B — `통화전송` (전화가 끊기면 그 파일을 올림)

| 순서 | 액션 |
|---|---|
| **트리거** | **전화를 끊으면(Call Ended)** → 아무 번호나 |
| 1 | **다음 동작 전까지 대기** 5초 ← 파일 마무리 시간. 삼성 통화 녹음은 통화 중 실시간으로 쓰기 때문에 통화 길이와 무관하게 5초면 됩니다 |
| 2 | **if (조건)** → 조건: MacroDroid 변수 `callfile` **!=** (값 칸 비워둠 = 빈 문자열) |
| 3 | ㄴ **HTTP 요청** POST `https://<터널주소>/call?number={call_number}&name={call_name}` |
| | ㄴ 본문 내용 = **파일** → 파일 선택 방식: **동적 파일 이름 / 스토리지 액세스 프레임워크(SAF)** → 폴더 = `Call`, 파일 이름 = `{v=callfile}`, 파라미터 이름 `file` |
| 4 | **End if** |
| 5 | **변수 설정** `callfile` = (빈 값) ← if **밖**에 둡니다. 매 통화마다 무조건 비워서 오래된 파일명이 남지 않게 |

동작 원리: A 는 **진짜 녹음 파일이 생겼을 때만** 파일명을 채웁니다. 부재중 전화는 녹음이 없으니 A 가 안 뜨고, B 의 if 가 빈 값이라 전송을 건너뜁니다. 전송 뒤엔 비워서 다음 부재중도 건너뜁니다.
상대 번호·이름은 녹음 파일에 없기 때문에 URL 쿼리(`number`, `name`)로 같이 보냅니다. 발신 통화용 매크로를 따로 두면 `&dir=out` 을 붙이세요.

MacroDroid 메뉴에서 실제로 누르는 순서(헤맨 자리):
1. 매크로 B 액션 **+** → 검색 "조건" → **"if (조건) … 동작"** 추가
2. 조건 추가 → 목록 맨 아래 **"MacroDroid 관련" → "MacroDroid 변수"** → `callfile` 선택 → 비교 **!=** → 값 칸 **빈 채로** 확인(빈 값 비교가 됩니다)
3. 액션 목록 오른쪽 **↕** 로 "if" 줄을 HTTP 요청 **위로** 드래그해서 HTTP 가 if 안쪽(들여쓰기)에 들어가게
4. 저장 ✓

## 4-4. 음성메모 전달 (선택 — STT 키 필요)

걸어가면서 "내일 3시 김OO 어머님 상담" 같은 걸 흘려 말하면 비서가 받아 적는 기능입니다.

녹음은 **폰 기본 녹음기 앱**으로 하고(잠금화면에서 녹음기 열어 녹음 → 정지 → 저장), 파일이 생기면 매크로가 올립니다.
MacroDroid 안에서 직접 녹음하는 방식은 버렸습니다(4-6절 ②·⑪).

| 항목 | 설정 |
|---|---|
| **트리거** | **변경된 파일** → 폴더: 녹음기 저장 폴더(갤럭시 = `Recordings/Voice Recorder`) / 파일 필터 `*.m4a` / **생성됨만 체크** |
| 액션 1 | 대기 3초 |
| 액션 2 | HTTP 요청 POST `https://<터널주소>/voice` , 본문 = 파일(동적 파일 이름 / SAF, 폴더 = `Voice Recorder`, 파일 이름 = `{file_name}`, 파라미터 이름 `file`) |

블루투스 이어폰 마이크로 녹음하고 싶으면 **삼성 녹음기 → 설정 → "사용 가능할 때 블루투스 마이크 사용"** 을 켭니다. 이 토글 하나가 답이고, 다른 녹음 앱·라우팅 앱은 전부 실패했습니다(4-6절 ⑩).

## 4-5. 서버에서 확인하는 법

```bash
journalctl -u inbox-server -n 50 --no-pager      # 도착했나, 401(토큰) 인가, 빈 본문인가, 모르는 키가 왔나(extra keys)
python3 scripts/inbox-ack.py --status            # 수신함 몇 건, 미처리 몇 건
tail -3 data/inbox.jsonl                         # 실제로 뭐가 들어왔나 (from / text / app)
```

MacroDroid 쪽은 왼쪽 메뉴 → **시스템 로그**에서 "발동했는지 / 변수에 실제로 뭐가 들어갔는지 / HTTP 응답 코드"를 봅니다.
**폰 로그의 발동 시각과 서버 journal 의 도착 시각이 초 단위로 맞으면 전송은 정상**이고, 문제는 내용(변수)입니다.

## 4-6. 시행착오 전부 (증상 → 원인 → 해결)

두 달 운영하며 실제로 겪은 것만, 겪은 순서대로 적었습니다.

### ① 알림 버튼 트리거를 만들었더니 권한 팝업이 무한 반복 (2시간 소모)
- **원인**: MacroDroid 의 알림 버튼·위젯 트리거는 **접근성 서비스** 권한을 요구하는데, 알림 접근 권한만 주고 접근성은 안 줬습니다.
- **해결**: 설정 → 접근성 → MacroDroid(UI 자동조작) 허용. 참고로 잠금화면 우측하단 바로가기는 삼성이 "앱 실행"만 허용해서 매크로 트리거로 못 씁니다.

### ② 서버 응답은 200인데 전사가 안 옴 → 서버 로그 `audio=0B`
- **원인**: MacroDroid 자체 녹음 액션이 `lecture.m4a` 를 **폴더로** 만들고 그 안에 타임스탬프 이름의 `.3gp` 를 저장했습니다. HTTP 액션은 `lecture.m4a` 를 파일로 읽어 0바이트를 보냈습니다.
- **해결**: 당시엔 녹음 파일명을 직접 지정하고 확장자를 `.3gp` 로 맞춰 해결. 지금은 아예 MacroDroid 녹음을 안 쓰고 기본 녹음기 + "변경된 파일" 트리거로 갔습니다(4-4절).

### ③ 발신 번호가 `{sms_number01012345678}` 처럼 깨져서 옴
- **원인**: 본문 파라미터를 손으로 타이핑하다 `from={sms_number{sms_name}}` 처럼 **변수 안에 변수**가 들어갔습니다.
- **해결**: 파라미터를 지우고 `...` 버튼으로 변수를 하나씩 삽입. 이후로 매직 텍스트는 손타이핑 금지.

### ④ 긴 문자(MMS)만 서버에 0건
- **헛다리 3연속**: "LMS 라서?" → "RCS 라서?" → "메시지 저장소를 직접 모니터링하자" 전부 아님.
- **원인**: 공식 문서에 있었습니다. **MacroDroid "SMS 수신" 트리거는 MMS 를 지원하지 않습니다.**
- **해결**: 트리거를 **알림 수신됨(메시지 앱)** 으로 교체, 본문 `from={not_title}&text={notification}`. 부작용은 `from` 이 번호 대신 연락처 이름으로 오고(앞뒤에 보이지 않는 유니코드 기호 U+2068/2069 가 붙음 → 서버가 벗김), 5120자 넘는 초장문은 잘립니다(일반 문자·MMS 는 실측 안 잘림).

### ⑤ 서버 필터가 사람 문자를 광고로 오인, 장난 문자는 "안 왔다"고 혼란
- **원인**: 서버에 "광고 같으면 건너뛰기" 필터를 뒀더니 진짜 문자를 먹었고, 반대로 걸러진 게 있는지 사람이 알 길이 없었습니다.
- **해결**: 건너뛰기 폐지. **전부 받고 비서가 라벨만 붙여 보고.** 폰에서도 무필터. 원장 지시 그대로: "스킵 전혀 하지 마라."
- **덤**: 내 폰에서 내 폰으로 보낸 테스트 문자는 알림이 안 떠서 트리거가 안 됩니다. 버그가 아니라 검증 방법이 틀린 것.

### ⑥ 통화 매크로 하나로 만들었더니 86KB 미완성 파일이 올라옴
- **원인**: 삼성 통화 녹음은 통화 **시작 시점에 파일을 만들고 실시간으로 씁니다.** "파일 생성 → 즉시 업로드" 매크로는 통화 시작 직후의 조각을 보냈습니다.
- **해결**: **두 매크로**로 분리 — A 는 파일 생성 시 이름만 변수에 저장, B 는 통화 종료 시 5초 기다렸다가 그 이름으로 업로드(4-3절).

### ⑦ 한글·공백이 들어간 파일 경로가 0바이트로 반복
- **원인**: 변수에 **전체 경로**를 넣고 "로컬 파일 URI" 방식으로 읽으니 `…/Call/통화 와이프_260623.m4a` 같은 한글·공백 절대경로를 MacroDroid 가 못 읽었습니다.
- **해결**: 변수엔 **파일 이름만**, 본문은 **SAF 폴더(`Call`) + 파일 이름 `{v=callfile}`** 조합 → 184KB 정상 도착.

### ⑧ 부재중 전화인데 "직전 통화" 내용이 또 요약돼 옴 (3연속)
- **증상**: 18:34 정상 통화 요약 → 19:04 부재중 전화 뒤 **똑같은 요약이 다른 번호 이름으로** 한 번 더. 가끔 5KB 짜리 깨진 조각이 올라와 전사 실패.
- **원인**: `callfile` 에 이전 값이 남아 있어 B 가 통화 종료마다 그걸 다시 쐈습니다.
- **해결**: B 에 `if callfile != 빈값` 가드 + 매 통화 종료 후 `callfile` 초기화(if 밖). 서버도 이중으로 **같은 오디오(sha256)가 6시간 안에 또 오면 버립니다**(`/call`). 정상 통화가 가드에 걸리면 대기를 5 → 8~10초로.

### ⑨ 카톡이 어느 날부터 조용히 0건 (8일간 모르고 지나감)
- **증상**: 문자·통화는 잘 오는데 카톡만 어느 날 이후 한 건도 안 옴. 에러도 없음.
- **헛다리 1**: "알림 접근 권한이 풀렸나 / 배터리 최적화에 걸렸나" → 같은 MacroDroid 가 문자·통화는 그날도 보내고 있었으니 **처음부터 아닌 걸 알 수 있었던 가설**. 절전 화면의 큰 숫자에 꽂혀 두 시간 낭비.
- **헛다리 2**: "방 이름을 바꾸셨나 / 방 알림을 꺼두셨나" → 캡처로 확인, 둘 다 아님.
- **진짜 원인**: 카톡 앱 업데이트로 알림이 **대화형(MessagingStyle) 형식**으로 바뀌면서, 방 이름이 매크로가 읽는 **제목 칸에서 다른 칸(대화 제목)으로 옮겨갔습니다.** 트리거에 걸어둔 조건 "알림 텍스트에 `선생님방` 포함"이 더는 어디에도 안 맞아서 발동을 안 한 것. 화면엔 방 이름이 멀쩡히 보이니 사람 눈엔 아무것도 안 바뀐 것처럼 보였습니다.
- **해결**: 트리거의 **포함 단어 조건을 지움** → 그 즉시 유입 재개. 방 이름이 담기는 변수를 찾으려고 후보 변수를 여러 개 실어 보내 서버 로그(`extra keys`)로 봤는데, **방 이름은 어느 변수에도 없었습니다**(티커는 "보낸사람 : 내용"). 그래서 방 단위 필터는 포기하고 **카톡 전체를 다 받고 비서가 내용으로 업무/잡담을 가르는** 구조로 확정.
- **교훈**: 필터가 갑자기 안 걸리면 "값이 바뀌었나"보다 **"값이 다른 자리로 갔나"** 를 먼저 의심. **필터는 관측할 수 없는 폰이 아니라 로그가 남는 서버에** 두세요. 소스별로 "48시간 0건이면 알려줘" 같은 침묵 감시를 두면 8일이 2일로 줄어듭니다.
- **잃은 것**: 그 8일치 단톡방 공지는 서버에 도착한 적이 없어서 복구 불가. 원장이 폰으로 스크롤해 봐야 했습니다.

### ⑩ 블루투스 이어폰 마이크로 녹음이 안 됨
- **헛다리**: 서드파티 녹음기(Hi-Q 등), 마이크 라우팅 앱(안드로이드 16 제한), MacroDroid "연결 도우미"(출력 A2DP 만 제어, 입력은 못 바꿈), 녹음기의 마이크 소스 선택창(전면/후면은 내부 마이크 종류일 뿐). USB-C 무선마이크 리시버는 되지만 꽂았다 뺐다가 번거로워 기각.
- **해결**: **삼성 기본 녹음기 → 설정 → "사용 가능할 때 블루투스 마이크 사용" ON.** 이게 진짜 스위치입니다. 음질은 전화 음질(8kHz)이지만 STT 에는 충분(4.3MB → 889자 온전 전사 확인).

### ⑪ "긴 녹음이면 3초 대기가 모자라 반쪽 올라가지 않을까"
- **결론**: 기우였습니다. 삼성 녹음기는 **정지 → 저장(확인) 시점에 파일을 만들기** 때문에 "생성됨" 트리거는 항상 완성본을 잡습니다. 대신 트리거 이벤트를 **생성됨만** 체크하세요. "수정됨"까지 켜면 저장 중 여러 번 발동해 반쪽이 여러 번 갑니다.

### ⑫ 매크로 "테스트 실행" 버튼을 누르면 `{notification}` 이 글자 그대로 옴
- **원인**: ▶ 테스트 실행은 **트리거를 건너뛰므로** 트리거가 채우는 변수가 전부 빈 값입니다. 고장이 아닙니다.
- **해결**: 카톡 매크로는 가족·지인에게 실제 카톡 한 통, 문자 매크로는 다른 폰에서 문자 한 통으로 테스트합니다.

### ⑬ 같은 카톡이 2~3번 연속 옴 (밀리초 간격)
- **원인**: 카톡이 알림을 갱신(그룹 요약·읽음 상태 변화)할 때마다 안드로이드는 새 알림 이벤트를 쏘고, MacroDroid 가 그때마다 발동합니다. 큰 텍스트 칸엔 최근 메시지 여러 줄이 누적돼 있기도 합니다.
- **해결**: 폰에서는 "그룹 요약 알림 무시"를 켜고, **서버가 60초 안 같은 발신자·같은 본문은 버립니다**(`inbox_server.py` 의 `_is_dup`). 폰 설정만으로는 완전히 못 막아서 서버 쪽 방어가 정답이었습니다. ("같은 알림 중복 무시"를 켜서 막으려 하면 진짜로 같은 내용을 두 번 보낸 문자까지 먹습니다 — 그건 끄세요.)

### ⑭ 서버 응답 401
- **원인**: 헤더 이름 오타, 토큰 앞뒤 공백, 토큰 회전 후 폰 미갱신.
- **해결**: 서버 `.env` 값과 매크로 헤더 값을 글자 단위로 대조. **토큰을 바꿨으면 매크로 4개 전부** 바꿔야 합니다(하나만 바꾸고 나머지가 조용히 401 나는 일이 실제로 있었습니다).

### ⑮ 폰에서 거르지 마라
- 처음엔 광고 문자·잡담 카톡을 폰 매크로 조건으로 걸러 보려 했습니다. 결과는 ⑨번 사고와 "새로 온 선생님 카톡을 명단에 없다고 조용히 버림"이었습니다.
- **원칙**: 폰은 **다 보내고**, 거르는 건 서버·비서가 합니다. 폰 쪽 필터는 고장 나도 아무도 모릅니다(조용히 0건). 서버 쪽 필터는 로그가 남습니다.

### ⑯ 터널 주소가 바뀜 (quick tunnel 재시작)
- **증상**: 어느 날부터 전부 안 옴, MacroDroid 로그엔 연결 실패.
- **해결**: 매크로 4개의 URL 호스트를 바꿉니다. 매번 귀찮으면 Cloudflare 에 도메인을 하나 붙여 **고정 주소 터널**(3단계 문서 참고)로 바꾸는 게 근본 해결입니다. 서버 쪽 경로 이름(`/sms` `/call` `/voice`)은 **절대 바꾸지 마세요** — 바꾸면 폰 매크로를 전부 다시 만져야 합니다.

### ⑰ 재부팅·업데이트 뒤 매크로가 꺼져 있음
- **원인**: MacroDroid 자동 시작 꺼짐, 또는 안드로이드 대규모 업데이트 뒤 알림 접근 권한이 초기화됨. 장시간 백그라운드 작업 중 삼성 절전이 앱을 죽이면 변수(플래그)가 켜진 채 남아 다음 발동이 꼬이기도 합니다.
- **해결**: 4-0 절 표를 다시 한 번. 꼬인 변수는 MacroDroid → 변수 화면에서 손으로 비웁니다. 서버 쪽 "48시간 침묵 감시"가 있으면 이걸 이틀 안에 잡습니다. 없으면 8일 갑니다(⑨).
